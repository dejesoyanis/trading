## ARCH-DEC-04 — SMQ-01, no status precedence

**Outcome:** DECIDED. Alternative 1.

**Decided, verbatim:**

> Keine Priorität; historische Statusbegriffe unverändert lassen

**Meaning.** There is no winning status among `OPEN P0`, `PROPOSED_FOR_ACCEPTANCE`, and `DESIGN_RESOLVED`. Each source keeps its own words. The ambiguity stays. Historical priority `P0`, `P1`, and `P2` is not a decision-lifecycle state.

**Sources.** SMQ-01 in [approval-requests.md](../status-model/approval-requests.md). DET-09/10 `## ADFR-CROSS`. ADFR JSON and CSV status words. The P0 and P1 resolution files. The 2026-11-14 consolidation sentence and the 2026-11-15 addendum that does not adopt that sentence as a reconciliation. ARCH-DEC-02, the paragraph that says which of those three words wins was not decided.

**Alternatives rejected.** Alternative 2, treating the amended JSON/CSV `status` as the only decision-lifecycle word. Alternative 3, treating a later `DESIGN_RESOLVED` label as replacing `OPEN P0` and `PROPOSED_FOR_ACCEPTANCE`.

**Rationale.** ARCH-DEC-02 left this choice unmade. Choosing a winner would silently equate words that the sources still print differently. The user refused that equivalence.

**Consequences.** The remaining XC-11 status-word conflict stays OPEN. [legacy-status-mapping.md](../status-model/legacy-status-mapping.md) keeps `REQUIRES_USER_DECISION` for the cross-source status crosswalk. A decision to have no precedence is not a decision that the historical statuses are equivalent. No default precedence is established. Source text, dates, and hashes are not rewritten so the labels agree.

**Exclusions.** This decision does not close XC-11. It does not change ADFR `status`, `verification`, or `lifecycle`. It does not relabel `OPEN P2` on `ADFR-CROSS-005`. It does not make `DESIGN_RESOLVED` mean verified, implemented, or live-authorized.

## ARCH-DEC-05 — SMQ-02, no closed lifecycle enum

**Outcome:** DECIDED. Alternative 1.

**Decided, verbatim:**

> Kein neues Enum und keine zusätzlichen Lifecycle-Zuordnungen

**Meaning.** The repository does not ratify `proposed`, `open`, `ratified_with_exceptions`, `superseded`, `rejected`, and `withdrawn` as a decision-lifecycle enum. No additional lifecycle assignment is made. The lifecycle facts already stored stay `SUPERSEDED` and `NOT_SUPERSEDED` only. `SUPERSEDED` is not withdrawn and is not rejected.

**Sources.** SMQ-02. ARCH-DEC-02, which stored only those two lifecycle literals. CR-B10 §9 "Alternatives rejected", which discards design alternatives of `ADFR-CR-B10-001` and is not a lifecycle of `ADFR-CROSS-005`.

**Alternatives rejected.** Alternative 2, ratifying the enum and leaving every row unassigned. Alternative 3, treating `SUPERSEDED` as withdrawn and rewriting `ADFR-CROSS-005`.

**Rationale.** Alternative 2 would publish a canonical-looking enum before any row uses `rejected` or `withdrawn`. Alternative 3 would contradict ARCH-DEC-02, which kept `ADFR-CROSS-005` at `status` `PROPOSED_FOR_ACCEPTANCE` and `verification` `NOT_VERIFIED`.

**Consequences.** Supersession semantics are unchanged. Exactly one lifecycle value remains `SUPERSEDED`: `ADFR-CROSS-005`, successor `ADFR-CR-B10-001`. The other 77 stay `NOT_SUPERSEDED`. That count is not acceptance. The proposed enum tokens stay `PROPOSED_NOT_RATIFIED` and unassigned.

**Exclusions.** This decision does not assign `REJECTED` or `WITHDRAWN` to any historical record. It does not delete a row. It does not verify the successor.

## ARCH-DEC-06 — SMQ-03, scoped local-test claims

**Outcome:** DECIDED. Alternative 1.

**Decided, verbatim:**

> Nur konkret getestete Teilkomponenten als lokal getestet behandeln

**Meaning.** `IMPLEMENTED_AND_LOCALLY_TESTED` is scoped evidence for explicitly named type-shell functionality. It is not evidence for the whole UD. It is not external broker verification. It is not database verification. It is not remote CI. It is not ADFR verification.

**Sources.** SMQ-03. UD-01, UD-02, UD-03, UD-04, UD-05, and UD-09 in [unresolved-decisions.md](../domain/unresolved-decisions.md), which already split a tested part from `IMPLEMENTATION_PENDING`. The M0-02A header `IMPLEMENTATION_NOT_VERIFIED`. Registry rows whose `status` is `NOT_IMPLEMENTED`. All 78 ADFR `verification` values.

**Alternatives rejected.** Alternative 2, promoting the parent UD to externally verified. Alternative 3, promoting related `CONFIRMED_DECISION` rows to a tested verification value.

**Rationale.** The UD lines already name the part that was locally tested and the remainder that was not. A local unit test does not show broker correctness, database-integration correctness, or a remote CI result.

**Consequences.** The phrase may be read as local evidence only for the named type-shell part. All 78 ADFR `verification` entries stay `NOT_VERIFIED`. Broker uniqueness stays `EVIDENCE_PENDING`. UD statuses are not rewritten by this decision. Passing `cargo test` in this workspace does not fill an ADFR verification cell.

**Exclusions.** This decision does not assign `IMPLEMENTED` or `VERIFIED` to an ADFR row, a registry row, or a source file. It does not pass B10-T01 through B10-T12. It does not run, and does not count as a pass, the ignored PostgreSQL integration test. Remote CI is not run and is not a pass.

## ARCH-DEC-07 — SMQ-04, evidence gate for a future verification change

**Outcome:** DECIDED. Alternative 1.

**Decided, verbatim:**

> Datierter Nutzerentscheid plus geeigneter Evidenznachweis

**Meaning.** This is a procedural gate. It is not approval of any present verification promotion. Before any ADFR `verification` value leaves `NOT_VERIFIED`, both of the following are required:

1. A dated explicit user approval that names the row and the exact claim.
2. An evidence record whose evidence is appropriate to that claim, containing all of: a URI or other stable artifact reference, the method, the environment, a timestamp, the exact claim and scope, and the limitations.

Ignored tests are not a pass. Remote CI that was not run is not a pass. `DESIGN_RESOLVED` is not external proof. An isolated local test is not external proof for a broker, database, or architectural-verification claim.

**Sources.** SMQ-04. All 78 ADFR `verification` values. ARCH-DEC-02. CR-B10 §9 `TESTS_NOT_EXECUTED` and B10-T01 through B10-T12. The P0 freigabeformel. Registry flags `live_trading_authorized` false, `canonical_schemas_published` false, `part_b` `NO-GO`, and `broker_uniqueness_evidence` `EVIDENCE_PENDING`.

**Alternatives rejected.** Alternative 2, letting a green local `cargo test` rewrite `verification`. Alternative 3, treating a source file's `DESIGN_RESOLVED` as enough to set a verified value.

**Rationale.** ARCH-DEC-01 and ARCH-DEC-02 already refused to treat a design label or a type-shell test as register verification. The user kept that refusal and added the record that a later promotion would need.

**Consequences.** The register is unchanged. Every `verification` value stays `NOT_VERIFIED`. No evidence record is filed by this decision, and no evidence URI is invented. A later promotion that lacks the dated approval or any listed evidence field is not authorized by this gate.

**Exclusions.** This decision does not change a current ADFR cell. It does not authorize live trading, canonical schema publication, or broker-uniqueness evidence. It does not convert `EVIDENCE_PENDING` into a verified uniqueness rule.

## ARCH-DEC-08 — SMQ-05, keep manifest provenance

**Outcome:** DECIDED. Alternative 1.

**Decided, verbatim:**

> Bestehende Manifestangaben beibehalten

**Meaning.** `placement`, intake hashes, current hashes, `reconstructed_draft`, `reviewed`, `approved`, and `source_text_status` stay as they are in [source-manifest.json](../source-manifest.json). The other ten package files are not labeled `original` and are not labeled `unknown`. This record does not claim original Q&A provenance for them. DET-01 and DET-02 keep reconstructed provenance and the ARCH-DEC-01 baseline with exceptions.

**Sources.** SMQ-05. Manifest rows: DET-01 and DET-02 have `reconstructed_draft` true and `source_text_status` `SOURCE_REVIEW_PENDING`. The other ten package files have `reconstructed_draft` false, `reviewed` false, and `approved` false. Their `placement` values are `COPIED_VERBATIM`, `REUSED_BYTE_IDENTICAL_EXISTING`, or `AMENDED_BY_ARCH_DEC_02`.

**Alternatives rejected.** Alternative 2, labeling every non-reconstructed package file `original`. Alternative 3, labeling every file that is not an original transcript `unknown`.

**Rationale.** Alternative 2 would call conversation-drafted contracts original transcripts. Alternative 3 would hide that the bytes are the package text identified by `package_sha256`. The manifest fields already say what is known.

**Consequences.** `contracts/source-manifest.json` is not edited by this decision, because no source file changes. `package_sha256` and `package_bytes` remain the TRD-ARCH-SYNC-01 intake values. Current `sha256` and `bytes` remain the repository file. They differ only where `placement` is `AMENDED_BY_ARCH_DEC_02`. The proposed provenance tokens `original`, `reconstructed`, `external_evidence`, and `unknown` stay `PROPOSED_NOT_RATIFIED` and are not assigned.

**Exclusions.** This decision does not set `approved` or `reviewed` to true. It does not clear `SOURCE_REVIEW_PENDING`. It does not accept an external broker-evidence file. DET-01 and DET-02 Q01–Q10 verification cells stay OPEN. `DESIGN_BASELINE_RATIFIED_WITH_EXCEPTIONS` remains the ARCH-DEC-01 label and is not widened.
